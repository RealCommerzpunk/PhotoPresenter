# PhotoPresenter

Zufällige Vollbild-Foto-Diashow für Windows und Linux (Electron + TypeScript).
Plan und Meilensteine: `docs/PLAN.md` · Änderungen je Version: `CHANGELOG.md` · Sitzungsprotokolle: `docs/sessions/Session-NNN.md` · Überblick für Menschen: `README.md` (Englisch, Haupt-README auf GitHub) und `README.de.md` (Deutsch) – beide inhaltlich gleich halten.

## Befehle

- `npm run demo`: App mit dem Demo-Datenordner `Data/` des Repos (Einstellungen + Gesichtsindex des Demo-Sets, nur `settings.json`/`faces.json` sind im Git). Das Demo-Set pflegt der Nutzer: in Tests nie `Data/` benutzen, sondern eine Kopie im Scratchpad per `PP_USER_DATA`
- `npm run dev`: App mit Hot Reload; `npm run dev -- --show` startet direkt die Show
- `npm run typecheck`, `npm run lint`, `npm test` (Vitest): vor jedem Commit alle drei (Vitest läuft mit `--configLoader=runner` und `pool: 'vmThreads'`, sonst bricht es unter Node 22.21 ab)
- `npm run models`: Modelle für die Gesichtserkennung nach `resources/models/` (nicht im Git, Prüfsummen im Skript); `dist` ruft das selbst auf
- `npm run quickstart`: `Quickstart.pdf` aus `Quickstart.md` neu erzeugen (nach jeder Änderung der Anleitung; die PDF kommt per `extraResources` ins Programm und ins Weitergabe-Paket)
- Icon: `build/icon.png`/`icon.ico` (electron-builder), `resources/icon.png` (Fenster per `iconPath()`, Fernbedienung `/icon.png`); Nennung „Three Musketeers – Flaticon“ muss erhalten bleiben
- Linux-Pakete entstehen im GitHub-Workflow (siehe oben), nicht lokal: AppImage/deb scheitern unter Windows an Symlinks (EPERM), und `electron-builder --linux tar.gz` verliert dort die Ausführungsrechte. `scripts/linux/pack.sh` packt `dist/linux-unpacked` mit Rechten zu den Archiven, `start.sh` nimmt `--no-sandbox`, wenn `chrome-sandbox` nicht SUID root ist. Der Rauchtest im Workflow wartet auf „Gesichtserkennung bereit“ im Log. `app.asar` ist seit 0.13.0 ~32 MB.
- Paketgröße: Nur Pakete, die der Hauptprozess zur Laufzeit lädt (externalisiert: `zod`, `exifr`, `qrcode`), gehören in `dependencies`; alles, was Vite in die Fenster bündelt (pixi, three, react, onnxruntime-web, gsap, Schriften), ist `devDependencies`, sonst landen die Pakete doppelt in `app.asar` (+250 MB). Neues Paket im Hauptprozess → `dependencies`, im Fenster → `devDependencies`; nach dem Bauen `out/main/index.js` auf `require("…")` prüfen.
- `npm run dist:win`: Installer lokal in `dist/` (Linux-Installer nur auf Linux/WSL)
- Session abschließen: `/session-ende`

## Arbeitsregeln

- **Kein CI, mit einer Ausnahme.** GitHub (`RealCommerzpunk/PhotoPresenter`, **öffentlich** seit 2026-11-13, Produktseite per GitHub Pages aus `main`/`docs`: https://realcommerzpunk.github.io/PhotoPresenter/) speichert den Code; Windows-Builds und Tests laufen lokal. Einziger Workflow: `.github/workflows/linux.yml` (Linux-Pakete AppImage/deb/tar.gz + Demo-Paket, mit Rauchtest), **nur von Hand** gestartet (`gh workflow run linux.yml -f release_tag=<tag>` hängt die Dateien an ein bestehendes Release). Keine weiteren Workflows und keine automatischen Auslöser ohne Rückfrage. Windows-Releases legen wir lokal gebaut per `gh release create` an. Alles Gepushte ist sofort öffentlich.
- **Nie den Bildschirm aufnehmen.** Zum visuellen Prüfen `PP_CAPTURE_DIR=<ordner>` setzen: Die App speichert dann im Entwicklungsmodus alle 2 s Bilder ihrer eigenen Fenster (`captureForTests` in `src/main/index.ts`). Testbilder und Aufnahmen gehören ins Scratchpad, nicht ins Repo.
- **Nie im echten Datenordner testen** (`%APPDATA%/PhotoPresenter`: Einstellungen, Personen, Gesichtsindex des Nutzers). Für jeden Testlauf `PP_USER_DATA=<scratchpad>/userdata` setzen (nur Entwicklung) und Testeinstellungen nur dort ablegen. Das gepackte Programm nutzt immer den echten Ordner.
- Produktseite: `docs/index.html` + `docs/media/` (GitHub Pages aus `main`/`docs`, Clips als animierte WebP aus `PP_CAPTURE_DIR`-Aufnahmen mit `PP_SHOW_SIZE=1280x720`, `PP_CAPTURE_MS=100`). Vorerst Deutsch. Neue Funktionen bei jedem Meilenstein dort nachziehen (Abschnitt, Fakten, Tasten); nichts Privates zeigen (Lieder aus `Songs/` nie aufnehmen – stattdessen Nachbildung mit Beispieltext). Sichtprüfung per Electron-Fenster (`offscreen`) bei 1280 und 390 px, auf waagrechte Überbreite achten.
- Release: `npm run dist:win`; Demo-ZIP `PhotoPresenter-Demo-<v>.zip` = portable exe + die in Git verfolgten `Photos/` und `Data/` (`settings.json`, `faces.json`) + `Quickstart.pdf` + zweisprachige `README.txt`; `gh release create v<v> --latest` mit Demo-ZIP, portabler exe und Installer. Linux: erst Vorabversion `v<v>-linux` anlegen, dann `gh workflow run linux.yml -f release_tag=v<v>-linux`. Danach Linux-Link in beiden READMEs anpassen.

Code steht unter MIT (`LICENSE`); neue Fremdinhalte (Bilder, Schriften, Modelle) in README/README.de.md unter „Credits“ nennen.

- Oberfläche, Kommentare, Commit-Nachrichten und Doku auf Deutsch.
- Versionen: `0.<meilenstein>.<patch>` in `package.json`, jeder Meilenstein ein Eintrag in `CHANGELOG.md`.
- Technische Namen (Ordner, Dateien, Schlüssel) auf Englisch (`Data`, `Photos`), Oberfläche und Doku vorerst auf Deutsch; Internationalisierung steht im Backlog (`docs/PLAN.md`).

## Architektur

- `src/main/remote.ts`: Fernbedienung. Logik in `RemoteServer.fetch` (Request → Response), der Node-Server reicht nur durch; das R-Fenster nutzt dieselbe Logik ohne Netzwerk (Sitzung `fernbedienung` mit `protocol.handle('http')`, Adresse `http://fernbedienung.local/`). Routen: `/` (`remote.html` per `?raw`), `/api/state`, `/api/settings` (nur `REMOTE_KEYS`), `/api/show` (`{cmd, arg}`), `/api/events` (SSE; Ereignis `notice` für Hinweise), `/api/photos`, `/api/thumb?n=`, `/api/queue`. Show meldet Zustand per `reportShowStatus` und Rückmeldungen per `notice`.
- `src/main/queue.ts`: manuelle Reihenfolge aus der Galerie (`QueueStore`, getestet); der laufende Eintrag (`playing`) steht vorn und fällt beim Weiterschalten heraus. Die Show bekommt die Liste per `IPC.queueChanged`, bevorzugt sie in `nextEntry()` und meldet per `queuePlaying`, was zu sehen ist; ändert sich die Liste, wird das vorbereitete Foto verworfen (ein normales wandert per `insertNext` hinter die Liste).
- `src/main/portable.ts`: Datenordner festlegen (`setupDataLocation`, vor `whenReady`): portable .exe/AppImage → `Data` neben der Datei (erster Start übernimmt `settings.json`/`faces.json` aus dem Benutzerordner), installiert nur wenn `Data` existiert; Chromium-Caches bleiben per `sessionData` im Benutzerordner. `exportPackage.ts`: Weitergabe-Paket (Programm, `Photos`, `Data`, `README.txt`). `faceIndexFile.ts`: Index-Datei Version 2 mit Pfaden relativ zum Fotoordner, `sameFile` mit 2 s Toleranz; weicht die Zeit ab, entscheidet `fileFingerprint` (Größe + SHA-1 über erste/letzte 64 KB, Feld `hash`), ob neu analysiert wird.
- `src/main/thumbs.ts`: Vorschaubilder der Galerie; das Analyse-Fenster rechnet sie (`thumbRequest`), Cache in `userData/thumbs`. Mit `face` ein quadratischer Gesichtsausschnitt (192 px) für die Personen-Seite, abrufbar als `photo://local/<foto>?face=x,y,w,h` (`faceThumbUrl`) – nie mehr ganze Fotos für Gesichtskacheln laden (zäh, große Vergrößerungen werden schwarz).
- `src/main/recent.ts`: Verlauf der gezeigten Fotos (`recent.json` im Datenordner, nicht im Weitergabe-Paket); die Show liest ihn beim Start (`recentPhotos`) und meldet jedes Foto (`photoShown`). `Playlist` (Einstellung `avoidRepeats`): `freshFirst` legt Fotos, die vor weniger als einer halben Runde zu sehen waren, ans Rundenende; `shownExternally` nimmt Zielfoto der 3D-Welt und Galerie-Fotos aus der laufenden Runde; `WorldScene` wählt das Ziel per `freshestAmong` (am längsten nicht gezeigt unter den gut gelegenen Kacheln).
- Fernbedienung und Einstellungen: Jede Einstellung steht in `REMOTE_KEYS` oder mit Grund in `REMOTE_EXCLUDED` (`src/shared/remote.ts`, Test `remote.test.ts`). Neue Einstellung → auch auf die Handy-Seite (Bausteine `sliderControl`, `switchControl`, `selectControl`, `colorControl`, `rangeControl` in `remote.html`, Texte als `remote.*`-Schlüssel).
- `FaceStore.entriesOfPhotos()`: nur Fotos des letzten Einlesens (der Index behält gelöschte/aussortierte Fotos, damit sie bei Rückkehr nicht neu analysiert werden); für Anzeige und Auswahl immer diese Methode, nicht `entriesInFolder()`. `src/main/photoInfo.ts`: EXIF per exifr für die Info-Tafel.
- `src/main/paths.ts` + `programDir()`/`photoFolder()` in `settings.ts`: Fotoordner immer über `photoFolder()` auflösen, nie `settings.photoFolder` direkt benutzen (kann relativ sein).
- `src/main/faces.ts`: `FaceStore` – Gesichtsindex `faces.json` (Schlüssel: absoluter Pfad), Warteschlange fürs Analyse-Fenster, Abgleich mit der Fokus-Person, Beispielgesichter
- `src/renderer/indexer/`: unsichtbares Analyse-Fenster mit onnxruntime-web (WASM, ein Thread): YuNet 640×640 BGR → `decodeYunet`, Ausrichtung per `similarityTransform` auf die ArcFace-Vorlage, SFace 112×112 RGB → 128er-Vektor
- `src/shared/faces.ts`: reine Gesichts-Mathematik und Typen (getestet)
- Übersetzungen: `src/shared/i18n/` (`de.ts` = Quelle, `en/es/fr.ts`, `index.ts` mit `t()`, `labelMap`, Sprachliste). Keine festen Oberflächentexte im Code: Schlüssel in alle vier Dateien, dann `t('schlüssel', { name })`; Mehrzahl `'{n} Foto|{n} Fotos'`. Auswahllisten (`*_LABELS`) sind `labelMap`-Proxys und folgen der Sprache. Die Show/der Hauptprozess setzen die Sprache aus `settings.language` (`applyLanguage`). Die Handy-Seite `remote.html` übersetzt ihre deutschen Quelltexte per Rückwärtssuche über `/api/i18n` (nur Schlüssel `remote.*`; Tests in `remoteI18n.test.ts` und `i18n.test.ts` halten Seite und Wörterbuch deckungsgleich). Doku, Changelog, Kommentare bleiben deutsch.
- Songs/Karaoke: `src/shared/lyrics.ts` (getestet: `parseLyrics` mit Überschrift, `[Abschnitt]`-Marken und LRC-Zeitmarken, `alignLyrics` verteilt nach Silben über das Gesangsfenster, `estimateVocalWindow` schätzt Anfang/Ende aus der Lautstärke – echte Gesangserkennung gibt es nicht, Korrektur je Lied über `songTiming`). `src/main/songs.ts` liest `Songs/` (MP3 + gleichnamige TXT, Name = Verbindung) und liefert Bytes per IPC (`listSongs`/`readSong`); `src/renderer/show/song.ts` (`SongPlayer`) spielt per Web Audio und zeichnet den Text in `#lyrics`. Taste S (Auswahl bei mehreren Liedern im Show-Fenster), Befehle `song`/`songStop`. **`Songs/` steht in `.gitignore`** (private Lieder, Repo ist öffentlich).
- Karaoke-Editor: `src/renderer/settings/SongSync.tsx` (in `SongsPage`, Knopf „Zeiten setzen“), zwei Schritte: Mitsingen (Fläche oder Leertaste halten = Anfang bis Ende einer Zeile, `REACTION` 0,1 s abgezogen) und Feinschliff (Canvas mit Wellenform aus `peaksOf`, Zeilen als Blöcke, Ränder per Maus ziehen; nur eingepasste Nachbarn begrenzen). Arbeitet auf `LyricRow[]` (`parseRows`/`serializeRows` halten die TXT-Struktur: Überschrift, `[Abschnitt]`, Leerzeilen, `[mm:ss.xx] Zeile`, eine Marke ohne Text direkt danach = Ende der Zeile); Anzeige der Zeiten über `alignLyrics` wie in der Show. Speichern per IPC `saveLyrics` (einmalig `.bak`). Test: `PP_SETTINGS_PAGE=Songs/sync` mit gebautem Stand und `PP_PROGRAM_DIR=<scratch>` (Kopie von `Songs` dort), `PP_SETTINGS_SCROLL="2 · Feinschliff"` für den unteren Teil. Der Nutzer fand Tasten-Editoren (Enter/E/Pfeile, Vorhalt, Tempo) unnatürlich – nicht wieder einführen.
- Kinder-Fernbedienung: Taste K (`toggleKidsWindow`), Handy-Adresse `/kids` (dieselbe `remote.html` im Kindermodus). Befehle `kidEmoji`/`kidText` erlaubt die Show höchstens einmal je Foto (`kidEmojiUsed`/`kidTextUsed`, Rücksetzen in `endManualExtras`, Zustand in `ShowStatus`).
- Dubletten: `src/shared/dupes.ts` (pHash aus 32 × 32 Graustufen per DCT, `findDuplicates` gruppiert bei Abstand ≤ 6 und gleichem Seitenverhältnis; geeicht: Kopien ≤ 2, Serienbilder ≥ 10). Das Analyse-Fenster rechnet den Hash (`phashOf`, bei Gesichtsanalyse mit, sonst Auftrag `kind: 'hash'`), `FaceStore` speichert ihn als `phash` und liefert `duplicates()`. `dupesClean.ts` verschiebt nach `Duplicates/` (von `listPhotos` ausgelassen) oder in den Papierkorb. Die Show bekommt bei `dupesSkip` die bereinigte Liste (`showPhotos` in `index.ts`).
- `src/main/`: Fenster, IPC, Einstellungen (`settings.ts`, JSON in userData, atomar geschrieben), Fotoliste und `photo://`-Protokoll (`photos.ts`, liefert nur Dateien aus dem gewählten Ordner, CORS freigegeben)
- `src/preload/`: `window.api` (Typ `PhotoPresenterApi` in `src/shared/ipc.ts`)
- `src/shared/`: `random.ts` (Range „von … bis“ + Zufall, gewichtete Auswahl, `seededRng`), `settings.ts` (zod-Schema; jedes Feld hat Standardwert und fällt bei ungültigem Inhalt darauf zurück)
- `src/renderer/settings/`: React + Tailwind v4; Bausteine `RangeInput`, `WeightedList`, `Select`, `Card`, `Field` in `controls.tsx`; Seiten `TextsPage`, `StylesPage`; `TextPreview` spielt Texte live ab
- `src/renderer/text/`: von Show und Einstellungen gemeinsam genutzt: `overlay.ts` (HTML-Text mit GSAP SplitText), `animations.ts`, `fonts.ts` (Fontsource-Imports), `resolve.ts` (Stil inkl. Zufall)
- `src/shared/text.ts`: Schemas für Texte und Stile, die 12 Stilvorlagen, Schriften, Animationsnamen
- `src/renderer/show/`: PixiJS v8
  - `loader.ts` (Haupt-Thread) schickt Aufträge an `loader.worker.ts`; die Bildarbeit steht in `imageprep.ts`: Laden mit EXIF-Drehung, Verkleinern auf Bildschirm × 1,35, weiche Kanten, Randfüllung (blur/ambient/mirror; mirror liegt deckungsgleich unter dem Foto). Das Foto kommt in Streifen à 320 Zeilen (2 px Überlappung) zurück; `main.ts` lädt sie einzeln pro Frame hoch (`uploadGradually`), `Slide` setzt sie zusammen
  - `motion.ts`: reine Bewegungsmathematik (`fitImage`, `planShot`, `planFocusShot`, `evaluateShot`); Pfade mit Stationen (`path`) für Schwenks über Gesichter; Versatz wird immer an den Bildrand begrenzt
  - `slide.ts`: ein Foto mit Bewegung über Einblenden + Stehen + Ausblenden
  - `transitions/`: `engine.ts` rendert altes und neues Foto je Frame in RenderTextures und mischt per Mesh-Shader; `shaders.ts` enthält die Effekte (`vec4 transition(vec2 uv)` mit `fromColor`/`toColor`). Neuer Effekt = Eintrag in `TRANSITIONS` (`settings.ts`) + GLSL-Body
  - `effects/particles.ts`: `EffectLayer`/`ParticleEffect` (PixiJS `ParticleContainer`, eine gemeinsame Formen-Textur, Effekte als `SPECS`); Ebene liegt über `transitions.view`. `effects/backgrounds.ts`: `AnimatedBackground` (Mesh-Shader) für Textfolien, Farben per `colorsFrom` aus dem Foto
  - `world/`: 3D-Zwischenspiel. `formations.ts` (reine Rechnung, getestet: Position + Blickpunkt je Kachel, Kamerastil je Formation; `density` aus `worldDensity` mischt per `mix` zwischen lockerem und dichtem Abstand, Kameraabstand zieht mit), `worldScene.ts` (`WorldScene` als `Scene`; Three.js zeichnet in ein eigenes Canvas, das jeden Frame als Pixi-Textur übernommen wird → läuft durch die Übergänge; Three wird per dynamischem Import nachgeladen; ein gemeinsamer Renderer für alle Zwischenspiele), `thumbPool.ts` (Vorschaubilder im Seitenverhältnis des Fotos aus dem Worker, nur in ruhigen Phasen; die Kachel zeigt die Mitte in 4:3). In der Show: `nextEntry()` schiebt `{ kind: 'world' }` ein, `sequencer.insertNext(final)` setzt danach mit dem Zielfoto fort
  - `playlist.ts`: Zufall ohne Wiederholung
  - `history.ts`: `ShowHistory` für ← und → über alle Einträge (Fotos, Textfolien, 3D-Welten). Ein `HistoryRecord` hält die Zufallsentscheidungen (Randfüllung, Textstile, Text-Hintergrund, `WorldReplay` mit Formation, Kachelnamen, Dauer, Zielkachel), damit Wiederholtes gleich aussieht. `upcoming()` in `main.ts`: nach dem Zurückblättern erst den Verlauf entlang, Galerie und „3D jetzt“ gehen vor; `Prepared` trägt `record` und `fresh`
  - Ein-/Ausstieg der 3D-Welt: Vor einer Welt `Slide.settleToWhole` (weich ins Gesamtbild), die Welt beginnt mit diesem Foto als scharfer Kachel (`WorldPlan.intro`, `loadThumb(name, höhe)`), Kamera erst exakt davor (`introFront`, Kamera-Oben wie die Kachel), dann zurück. Beim Eintauchen zieht die Zielkachel vom 4:3-Ausschnitt zum ganzen Foto auf (`cropTexture`; Vorschaubilder haben das Seitenverhältnis des Fotos) und bekommt per `setFinalSharp` eine scharfe Fassung. Die Randfüllung zeigt die Welt selbst: Sprites unter dem Three-Bild (`setFinalBackdrop`, `intro.backdrop`, Kopie per `LoadedPhoto.copyBackdrop`), der Three-Renderer hat `alpha: true` und löscht mit `setClearColor(bg, 1 − Stärke)` (kein `scene.background`). Übergang Welt ↔ Foto ist eine kurze `fade` (≤ 0,7 s); `placeBackdrop` (in `slide.ts`) legt den Rand in Welt und Slide gleich
  - `world/crop.ts`: `tileCropCenter` legt den 4:3-Ausschnitt je Kachel ohne Zoom so, dass Fokus-Person/Partner, sonst alle Gesichter zu sehen sind (Hochformat ohne Gesichter etwas oben); `prepareWorld` holt dafür `getFaces(name, true)` je Kachel, `WorldTile.crop`. Die scharfe Zielkachel bekommt dieselbe weiche Kante wie das Vollbild (`loadThumb(name, höhe, feather)`, `featherFraction`), angefordert, sobald das Zielfoto geladen ist. Karussell/Welle: Blickpunkt per `ringLookY` bzw. `centerZ` in `formationInfo` mittig
  - `world/paper.ts`: 12 Rückseiten aus Fotopapier, per `seededRng` einmal erzeugt (Canvas, keine Dateien); Rückseite je Kachel fest nach `hash01(i, 31)`
  - Tasten p/P: `focusNow` → `Slide.refocus` (Pfad: aktuelle Kamera → Gesamtbild → Fokus-Stationen, Bewegungszeit startet neu über `restart`); `getFaces(name, true)` markiert Person/Partner auch bei ausgeschaltetem Fokus
  - `sequencer.ts`: Reihenfolge aus Fotos, Fülltexten und gebundenen Texten (vor/über/nach)
  - `scene.ts`: gemeinsame Schnittstelle `Scene` für `Slide` (Foto) und `TextSlide`; `OverlayTrack` steuert Texte zeitlich
  - `faceAvoid.ts`: Gesichter auf dem Bildschirm (`faceOnScreen`, mit Rand) und Platzwahl (`bestPlace`); `Slide.upcomingFaces(s)` liefert sie für Sofort-Texte/Emojis, Texte über Fotos wählen per `TextOverlay.placeAvoiding` (gemessen ohne Animations-Transform). Die Show lädt die Gesichter je Foto immer (`faces: null` = nicht analysiert)
  - Auf dem Show-Bildschirm nur bewusst Eingeblendetes (Texte, Emojis, QR-Codes, Info-Tafel, fps auf Taste D): `flashStatus` zeigt nichts an, Rückmeldungen gehen per `notice` an die Fernbedienung (Nutzerwunsch)
  - `emojis.ts`: schwebende Emojis (HTML + GSAP) über dem Foto; `info.ts`: Info-Tafel (Taste I)
  - `main.ts`: Ablauf, Vorladen, Tasten. Per Hand Ausgelöstes (Effekte, Sofort-Texte, Emojis) endet in `endManualExtras()` beim nächsten Übergang. Einfrieren: `Slide.setFrozen` (Fortschritt pendelt als Sinus um die aktuelle Stelle, Auftauen setzt dort fort)

## Stolperfallen

- Die Fenster laufen mit `sandbox: true`: Der Preload muss CommonJS sein, deshalb kein `"type": "module"` in `package.json` (ESLint-Konfiguration ist `.mjs`).
- `import 'pixi.js/unsafe-eval'` muss vor PixiJS geladen werden, weil die CSP kein eval erlaubt.
- Ruckelfreiheit: Im Übergang keine Zusatzarbeit (Vorladen startet erst bei "Übergang Ende"); Worker-Canvas mit `willReadFrequently` (CPU), sonst konkurriert er mit WebGL; beim Übergangsstart sofort `transitions.render(…, 0)`, sonst zeigt die Übergangsfläche einen Frame lang alten Inhalt. Änderungen an der Show mit `PP_PERF=1` messen, und zwar ohne `PP_CAPTURE_DIR` (die Aufnahmen verfälschen die Bildrate).
- Neue Datenquellen in der Show brauchen einen Eintrag in der CSP beider `index.html`.
- Neue Auswahl-Optionen (Effekte, Bewegungsarten, Füllmodi) nur hinten an die Konstanten in `settings.ts` anhängen; `parseSettings` ergänzt sie in gespeicherten Einstellungen. Ein entfernter Eintrag setzt die ganze Liste auf Standard zurück.
- Gesichtskoordinaten im Index sind relativ (0–1) zum bereits EXIF-gedrehten Bild; Show und Analyse dekodieren beide mit `imageOrientation: 'from-image'`.
- Beispiele und Gegenbeispiele (`Person.samples`/`negatives`) werden am Merkmalsvektor (`emb`) erkannt, nicht an der Gesichtsnummer. Treffer = über der Schwelle und ähnlicher als jedes Gegenbeispiel (`matchFace`).
- Hand-Markierung: `markFace` → Analyse-Fenster (`analyzeBox`) sucht im Ausschnitt neu; überlappt das Ergebnis ein vorhandenes Gesicht (IoU > 0,5), wird es ersetzt und Zuordnungen ziehen mit. Von Hand markierte Gesichter (`manual`) überstehen das Neu-Analysieren.
- `FaceStore` nimmt den aktuellen Ordner aus den Einstellungen, nicht aus dem letzten Einlesen (sonst findet die Show beim Start keine Gesichter).
- Zum Testen der Erkennung: OpenCV-Beispielbilder (`lena.jpg`, `messi5.jpg`) ins Scratchpad laden, nie ins Repo. Gleiche Person ≈ 0,8–0,93, verschiedene ≈ 0,13–0,18 (Schwelle 0,38).
- Textgrößen sind in `cqh` angegeben: Der Host-Container eines `TextOverlay` braucht `container-type: size`.
- Texte und eigene Stile werden in `parseSettings` Eintrag für Eintrag geprüft (`parseList`), damit ein kaputter Eintrag nicht alle Texte löscht. In zod 4 müssen solche losen Felder `z.unknown().optional()` sein.
- Frame-Messung: `PP_PERF=1` lädt die Show mit `#perf`; langsame Frames (> 25 ms) erscheinen mit den Ereignissen davor im Terminal (`perf.ts`).
- Weitere Testschalter (nur Entwicklung): `PP_PROGRAM_DIR` (so tun, als läge das Programm dort; mit `PP_USER_DATA=<dir>/Data` ein Paket „auf einem anderen Rechner“ starten), `PP_TEST_EXPORT=<ordner>` (erstellt dort ein Paket), `PP_CAPTURE_MS` (Aufnahme-Abstand, z. B. 500 für schnelle Abläufe), `PP_CAPTURE_WIDTH` (Breite der Aufnahmen, Standard 960), `PP_SHOW_SIZE=1280x720` (feste Größe der Fenster-Vorschau, für Bilder der Produktseite), `PP_SETTINGS_SCROLL=<Kartentitel>` (Einstellungen scrollen zu dieser Karte).
- Fernbedienung testen: **nicht per curl** – die Sandbox der Shell leitet 127.0.0.1 an den echten Rechner weiter, dort laufen evtl. die echte App oder andere Programme. Stattdessen `PP_TEST_COMMANDS="7:emoji:❤️;8:freeze:on;9:key:i;10:queue:foto.jpg;12:drag:x1,y1,x2,y2"` (Sekunden:Befehl:Zusatz, nur Entwicklung) und die Handy-Seite mit `PP_REMOTE_PREVIEW=1|zoom|fotos` (läuft ohne Netzwerk, mit `PP_CAPTURE_DIR` als Aufnahme). Beim ersten Öffnen des Ports fragt die Windows-Firewall.
- Befehle an die Show haben einen optionalen Zusatz (`{ cmd, arg }`): `effect`/`world` mit ID, `text` mit Text-ID, `say` mit freiem Text. Sofort eingeblendete Texte laufen unabhängig vom Ablauf (`instantTexts` in `show/main.ts`).
- Nach der 3D-Welt: Sobald das Zielfoto geladen ist, ruft die Show `WorldScene.setFinalFrame(w, h)` (Größe des eingepassten Fotos); Kamera-Abstand und Seitenverhältnis der Zielkachel passen sich weich an, der Übergang startet erst bei `frameSettled`. Das Foto beginnt mit `softStart` im Gesamtbild (Zoom 1, mittig), die Bewegung läuft weich an; der Rand ist dann schon da (zeigt die Welt beim Eintauchen).
- 3D-Zwischenspiel: eine Formation; das Zielfoto wird erst beim Eintauchen gewählt (`WorldScene.chooseFinal`), deshalb lädt die Show während der 3D-Welt erst bei `diving` vor. Wackelpudding = `JELLY_VERTEX` (ersetzt three.js `project_vertex`) auf fein unterteilten Kacheln.
- Testeinstellungen mit Auswahllisten immer vollständig angeben: `parseSettings` ergänzt fehlende Optionen als aktiv.
- Ein zusätzlicher WebGL-Kontext (wie Three.js für die 3D-Welt) muss sein Bild als Pixi-Textur abgeben (Canvas → `Texture.from`, je Frame `source.update()`), sonst läuft er nicht durch die Übergänge. Kleinere Effekte lieber als Pixi-Partikel oder Mesh-Shader.
- `electron-vite preview --skipBuild` startet den zuletzt gebauten Stand – nach Codeänderungen ohne `--skipBuild` testen.
- Windows kann zusammengeschaltete Monitore als einen Bildschirm melden (z. B. 5760×1134). Dafür gibt es `showDisplay` (Display-ID, leer = Maus) und `showArea` (Drittel/Hälften, Rechnung in `src/shared/display.ts`); ein Teilbereich ist ein randloses Fenster mit `alwaysOnTop('screen-saver')` statt Vollbild. Für Tests `PP_SHOW_WINDOWED=1` (Fenster-Vorschau im Seitenverhältnis des Bereichs) – nie die echte Vollbild-Show über den Bildschirm des Nutzers legen.
- `npm run dev` zeigt die Einstellungen (React) hier teils leer ("Invalid hook call", doppeltes React durch den Dev-Optimierer, auch ohne eigene Änderungen); für Aufnahmen der Einstellungsseiten `npx electron-vite build` und `electron-vite preview --skipBuild`. Songs beim Testen mit `songVolume: 0` in den Testeinstellungen, sonst spielt es auf den Lautsprechern.
- Zoom immer mit `limitShot(…, zoomLimit(…))` begrenzen (Einstellung `maxUpscale`).
- Shell-Fallen: Backslashes, Regex und Template-Strings in `node -e`/Heredocs gehen leicht kaputt – bei so etwas Edit/Write oder ein Skript im Scratchpad benutzen.
- `npm run quickstart` scheitert mit EBUSY, wenn der Nutzer `Quickstart.pdf` geöffnet hat: Nutzer bitten, sie zu schließen. Für Clips gibt es kein ffmpeg (Download wurde abgelehnt) → animierte WebP mit Pillow; Edge headless liefert hier keine Screenshots → Seiten mit einem Electron-Fenster (`offscreen`) abfotografieren.
- Visuelle Tests der Einstellungen: `PP_SETTINGS_PAGE=Texte` (Seitenname) zusammen mit `PP_CAPTURE_DIR`.
- npm 11 blockiert Install-Skripte; Freigaben stehen in `allowScripts` in `package.json`. Electron lädt seine Binärdatei beim ersten Start selbst.
